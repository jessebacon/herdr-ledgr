# ledgr

A Herdr desktop-app mod that puts a two-direction request ledger beside a linear agent conversation: questions you park while the agent is still talking, and asks the agent makes of you, both held outside the transcript and anchored to the passage they came from. Phase 2 adds a Branch action that forks a parked question into its own session with an honest manifest of what the branch knows. Phase 3 adds the rejoin ("confluence"): one approved message carried back to the end of the trunk. Pins keep passages of a reply verbatim, with no question yet, so a later question can carry them as its context into the trunk or a branch.

Thesis in one line: keep a linear trunk, make non-linearity cheap and visible around it, and let a branch return its result, never its transcript.

## The one rule that matters

**This repo is the source of truth. The live install is a copy.** Edit here, then run `./install.sh` (the maintainer's own machine: `./install.sh --yes --answers examples/personal-overlay/answers.local.json`, his real answers, gitignored). Never edit `~/.config/herdr-app/mods/ledgr`, `mods/ledgr-pane` or `mods/my-tabs` in place. If an agent did edit the live copy (it happens during a build), run `./sync-from-live.sh` once to pull the changes back (it pulls the overlay mods into `examples/personal-overlay/`), review the diff, and go back to editing here.

Why a copy and not a symlink: Herdr refuses any import that resolves outside a mod's own folder, symlinks included, and the Claude Code hooks (in `~/.claude/settings.json` and each other chosen config folder's, `~/.claude-work/settings.json` in the examples) and the MCP server (in each folder's `.claude.json`) are registered against the installed path.

## Architecture in seven lines

1. Claude Code hooks (SessionStart, UserPromptSubmit, Stop) run `mods/ledgr/bin/adapters/claude/*.sh`. They inherit `HC_TERMINAL_ID` from the Herdr shell, so they can map terminal to session id, transcript path, cwd and turn; SessionStart and UserPromptSubmit also read the terminal's Herdr space (one `hc get $HC_TERMINAL_ID --json`, 300 ms limit, `ledgr_map.herdr_space()`) and record it. In a space listed in `spaces.disabled` they go quiet: the record and the map are written, but no spool event, no instruction, no landing and no extraction (`asks-instruction-space-off.txt` once to a session switched off, the mode's wording once when it is on again). They exit 0 fast, print nothing to the model's context except the ledgr-asks instruction (SessionStart, once after a missed blocker, once after an `asks.handoff` change), and ignore child or subagent processes (`LEDGR_INNER`, owner-pid rule).
2. Everything that changes state is a JSON event dropped into `~/.config/herdr-app/ledgr-data/spool/` with an atomic write: hooks, the capture box, panel actions, and the MCP server (`bin/mcp/ledgr_mcp.py`). `bin/lib/ledgr_spool.py` is the contract and has no Claude-specific imports.
3. One writer applies the spool to `ledgr-data/store.json` (source of truth) and `snapshot.json` (what the extractor reads), then deletes the spool file. The writer runs in an always-shown host copy because a panel block's mod copy only starts when first shown: the `ledgr` host block (props `{view: "host"}`, role `host`), or a mod with an engine copy (the maintainer's `my-tabs`, role `my-tabs`). Hosts elect one holder of `shared("ledgr.writer")`; the panel is a reader of `store.json` and falls back to being the writer only if no host answers within 4 s. Never claim or ping from `herdr-app check` (it shares the window's shared state on 0.1.13): `config.js` `liveHome()` guards it.
4. Asks are declared first (by the MCP tool `declare_asks` when registered, else by a block), extracted as the fallback. The SessionStart hook puts the ledgr-asks instruction for the `asks.handoff` mode (`bin/lib/asks-instruction-ledgr.txt` or `-both.txt`; `prose` prints none; `instruct_block` stays the master switch) into the session's context, so the agent declares a blocker or a needed decision with `declare_asks` (written to `ledgr-data/mcp/<session>/<turn>.json` and spooled at once) or, without the tool, a fenced `ledgr-asks` block (bullets; a JSON array is still read). At Stop the extractor emits `pending`, resolves the turn's message uuid, and settles the tool declaration or reads that block (no model call); only a reply with neither goes to `claude-haiku-5-5` with forced JSON output (provider seam: `anthropic`, `openai-compatible`, `cli`). A blocking ask only the model found marks the session, and its next real prompt carries the instruction once (`instruct_reinject`). Either way it emits `asks`. Asks close three ways besides the person's Done: the agent's `resolve_asks` (when the user's message answers or drops one; `resolvedBy: "agent"`), a landed confluence (`"branch"`), or an answer that took (an ask answered by an `[A3]` ref or the answer sheet becomes `resolved`, `resolvedBy: "answer"`, at that turn's `asks` event unless the reply raised it again). A session in a space where ledgr is off declares nothing: it gets the off text instead of the instruction, and the MCP server writes nothing and answers `off: true`. An adapter's job is the instruction and the turns (`bin/adapters/README.md`); everything else is agent-neutral. Every ask carries a `level` (blocking, needed, optional); `extract.threshold` in `config.json` (shipped default needed; the maintainer's live config says blocking) decides which are open rows that count on the chip, and the rest are kept as folded suggestions.
5. Capture (`cmd-j`, `mod.open:ledgr`) opens over a working pane, parks a question with one keystroke, and accepts a clipboard quote only if it matches the saved turn text or `hc read`.
6. A message meant for an agent's prompt (the answer sheet, one answer, a confluence) is staged on the clipboard, its pane focused, and then pasted with Herdr's `terminal.paste` (what ⌘V runs) once Herdr reports that terminal focused on two looks in a row with the clipboard unchanged (`nav.js` `stageIntoPrompt`, `ui.pasteIntoPrompt`, default on). Never into a terminal with no agent or an agent waiting on its own prompt, and never Enter: the person adds a word of their own and sends it. When the focus is not confirmed within 600 ms, or the switch is off, it stays clipboard plus focus, as Go to anchor, Copy for prompt, `/btw` and Ask for a conclusion always are. ledgr sends no keystrokes to any terminal: never `hc send` (it presses Enter and would submit a draft already in the prompt), never `hc keys` (Go to anchor pressed `ctrl+o /` until 2026-11-06; ctrl+o toggles Claude's transcript viewer), never `terminal.search`. `bin/tests/test_no_keystrokes.py` and `test_nav.mjs` enforce it (`terminal.paste` only inside `stageIntoPrompt`, without arguments, after the focus check). A staged confluence or answer sheet starts with a marker line (`ledgr confluence <branch> <item>`, `ledgr answers <session>`); the trunk's UserPromptSubmit hook sees it land and emits `confluence_landed` / `answers_landed` (`bin/lib/ledgr_landing.py`, `mods/ledgr/confluence.js`), one event per message when a prompt holds several (`detect_all`). Every staged message ends with one empty line (`nav.js` `promptText`), so a second paste into the same prompt does not run into the first.
7. Pins (`docs/design/Pins.md`, `docs/build-notes/BUILD-NOTES-pins.md`). In the capture box, ⌘S (`mod:ledgr` `"cmd-s": "ledgr.pin"`; `pinning.js` `PIN_KEY` and `pinDraft`) writes a `pin` spool event: the copied passage (up to 4,000 characters, line breaks kept), the box's line as its note, and an anchor (turn plus passage hash, uuid when known, never a position) from where the passage was found: a saved turn, else the screen (`hc read`), else unverified on a second ⌘S within 5 s. The writer keeps pins in their own `pins` map in `store.json`, beside `items`, so nothing that reads items (chips, counts, `snapshot.json`, refs, the archive, Forget) ever sees one; each pin carries its session's `source`, and the panel's `pin_note`, `pin_archive`, `pin_restore`, `pin_delete` apply by pin id even after Forget. A parked question carries pins through the box's `capture` Request (`request.pins`, at most 12, validated). Ask here stages `confluence.js` `pinsMessage` (marker `ledgr pins <session> <item>`, each passage quoted with `> ` and its provenance) through the paste of line 6; the trunk's hook emits `pins_asked` (quoted lines land nothing and give no refs: `ledgr_map.prompt_refs`), the question shows sent and is answered at that turn's Stop, and each pin records `answeredIn`. In a branch, `branch.js` `preamble` quotes the pins, the manifest gains a Given row, more than 24,000 pinned characters refuse the branch, Conclude prefills one entry per pin, and a landed confluence records `answeredIn` via the branch. No MCP tool reads pins yet.

## Engine copies (keep in sync)

Because of the import rule, a host in another mod (the overlay's `my-tabs`) cannot import from `mods/ledgr/`. `install.sh` copies the engine files into `mods/<host>/ledgr/` for every mod that imports `./ledgr/…` and verifies they are identical; the panel warns on drift. The list is `ENGINE_FILES` in `mods/ledgr/writer.js` (the installer reads it from there). If the writer gains a module, add it there. The copies are generated and never in the repo. The public install needs none: the host block lives inside `mods/ledgr`.

## Constraints that are not negotiable

- ledgr is a Herdr mod. It never reaches outside Herdr's home and the chosen Claude config folders (`~/.claude`, any second one such as `~/.claude-work`, and their `.claude.json` for the MCP registration); the installer also keeps its state in `~/.local/state/ledgr` and reads `~/.local/bin` wrappers and shell start-up files to find config folders. No Things 3, no other applications, no outbound calls except the extraction provider (the MCP server makes none). No keystrokes into any terminal, and never Enter; the only write into a terminal is `terminal.paste` after its focus is confirmed (`ui.pasteIntoPrompt`).
- Shipped Herdr mods and layouts are read-only; the installer patches only a personal layout (offering `layout.clone` first). The maintainer's layout is `layouts/custom.json`; Kolczyk replaces the spaces block there, leave it alone.
- `herdr-app check mods/<name>` must pass for every touched mod. `herdr-app shot` returns the last painted frame; an inactive window does not repaint, so a stale shot is not evidence of failure.
- Do not fork or exercise large live sessions in tests. Create a throwaway Claude session in a scratch directory and branch from that; close test panes; remove test items through the panel's own spool events, never by editing `store.json` by hand.
- Back up any live file you edit to `~/.local/state/ledgr/backup-<date>/` first.
- Python core, no Node. This machine has no Homebrew jq or curl; use `python3 -I`.
- Depth cap for branches is a default (`branch.maxDepth`, 2), not a law. Honor the config value.

## Vocabulary

trunk (the main linear session) · park (capture a question without sending it) · lane (pins on top, then your questions, then asks of you) · pin (a passage of an agent's reply kept verbatim with its anchor and provenance, with no question yet; it lives on, through Forget and past the transcript, and a question quotes pins as its context) · held (the panel staying on one session instead of following the focused pane; the header's hold control, "pinned" until 2026-11-07) · ask (something the agent needs you to decide or do) · anchor (session + turn + passage hash, uuid optional) · branch (a forked session born from a parked question) · manifest (what a branch knows and does not know) · confluence (the one message a branch returns to the trunk) · landing (the trunk's hook seeing a staged message submitted) · spool (the event inbox) · writer (the single process that applies it) · off (a space where ledgr does nothing: no instruction, no extraction, no chip, no capture).

## Design decisions log

- 2026-11-05 Research report concluded: chat-first trunk with cheap side moves, canvas last; the river metaphor survives only as "a tributary delivers its water, not its watershed". Evidence for lower cognitive load from branching UIs is thin; the value is navigation and model isolation.
- 2026-11-05 Jesse: the agent's asks of the human are a first-class lane, addressed directly in Phase 1 (the critique argued for deferring it; rejected).
- 2026-11-05 Jesse: extraction = model call at Stop with a structured block fast path. The SessionStart instruction that asks Claude to emit the block defaults OFF (it injects into the trunk's context and the block clutters forked transcripts). Superseded 2026-11-06: declared first, instruction on by default (below).
- 2026-11-05 Jesse: naming: "ledgr", in the spirit of "herdr".
- 2026-11-05 Jesse: no Things 3, no external applications, ever.
- 2026-11-05 From the Grok critique, adopted: store.json as source of truth with restore-before-ingest; clipboard quote validation; owner-pid and `LEDGR_INNER` guards; `pending` event; dismissed asks can be re-raised (`repeat_of`); parked questions are the top lane. Rejected: dropping the agent lane; "subagent_type fork is unconfirmed" (it is confirmed by the Claude Code harness itself).
- 2026-11-05 Writer moved to `my-tabs` because a hidden panel's mod copy does not start until shown. Since 0.1.0 the public host is the `ledgr` host block; `my-tabs` hosts it only in the maintainer's overlay.
- 2026-11-05 Phase 3: the confluence is clipboard plus focus, never `hc send`; landing is detected by a marker line in the trunk's UserPromptSubmit hook: the first line of any pasted block (Claude Code wraps pastes in `<pasted_content id="…">` lines), or unwrapped the prompt's first line or second after a one-line lead-in; never inside a code fence. The panel suggests typing a lead-in ("Adopt this branch result for Q1:") before pasting, and the message's last line is the person's assertion ("I am adopting this branch's conclusion as the answer to Q1; …"), because Claude Code presents a paste as possibly not the person's words. Item `rejoin_pending` then `resolved` with `resolvedBy: "branch"`; branch `concluded` then `rejoined`; one line per landing in `ledgr-data/sessions/<sid>/decisions.md`. Close branch (after rejoin) runs `hc kill` + `hc rm` and keeps the record.
- 2026-11-05 Jesse: ask severity. Every agent ask has one `level`: `blocking` (the agent stopped or cannot complete the task without this from the human), `needed` (the human must act or decide for the task to be truly finished, but the agent went on), `optional` (a suggestion, an offer, a nice-to-have). Judged by what the task needs, never by tone: a polite offer that wraps something only the human can give is blocking. `kind` stays. A `ledgr-asks` block item without a level is needed; an unknown level is rejected. `extract.threshold` (default needed) splits open rows that count on the chip from suggestions, which are still stored, fold at the bottom of their turn, and promote with one click; open blocking asks sort first and give the chip its own `blocking` state. Offers are now extracted (as optional) instead of dropped. Same day: lane folds are the person's alone (`ui.foldAsksWhileWorking` restores the old auto-fold), and motion runs only on detected state changes (`ui.animations`).
- 2026-11-05 and 2026-11-06, from Jesse's screenshots, the extraction prompt: a closer that only offers to go on ("ready to commit when you've had a look") is optional unless the agent says it cannot proceed; a statement of what is done, pending or uncommitted is never an ask; the quote is the one or two sentences that make the ask, never the whole message. Jesse's live threshold is `blocking` (2026-11-06); the shipped default stays `needed`.
- 2026-11-06 Public shape (0.1.0): the writer's public host is a view of the `ledgr` mod itself (`{view: "host"}`, a small always-visible button), so the mod installs alone and needs no engine copy; the chip is an optional mod (`ledgr-pane`) that only reads shared state; the maintainer's `my-tabs`/`my-pane` are an overlay (`examples/personal-overlay`), one answer to the host and chip questions, not a code path. One `install.sh` (interactive, `--yes --answers`, `--check`) and `uninstall.sh` that restores the pre-ledgr files when only ledgr's entries differ. Reason: Herdr's manual expects a shared mod to be `mods/<name>/` plus `keys.json`, a recipe and a preview, installable without the author's other mods.
- 2026-11-06 Jesse: ledgr never sends keystrokes to a terminal. Go to anchor pressed `ctrl+o /` through `hc keys`, and `ctrl+o` toggles Claude Code's transcript viewer, so the same keys could enter it or leave it and drop `/` into the prompt; Jesse saw a stray "detailed transcript" toggle. - 2026-11-06 Jesse: MIT license confirmed (`LICENSE`).

- 2026-11-06 Panel focus: it follows the focused pane across spaces; a focused agent pane with no ledgr session shows "no ledgr session yet" instead of the last session, and pinning is an `accent` "pinned" pill. Found while fixing it: one pane runs a second account (`claude-work` in the examples, `CLAUDE_CONFIG_DIR=~/.claude-work`), whose settings.json has no ledgr hooks, so that session never joins until the entries are added there.
