# ledgr

A Herdr desktop-app mod that puts a two-direction request ledger beside a linear agent conversation: questions you park while the agent is still talking, and asks the agent makes of you, both held outside the transcript and anchored to the passage they came from. Phase 2 adds a Branch action that forks a parked question into its own session with an honest manifest of what the branch knows. Phase 3 adds the rejoin ("confluence"): one approved message carried back to the end of the trunk. Pins keep passages of a reply verbatim, with no question yet, so a later question can carry them as its context into the trunk or a branch.

Thesis in one line: keep a linear trunk, make non-linearity cheap and visible around it, and let a branch return its result, never its transcript.

## The one rule that matters

**This repo is the source of truth. The live install is a copy.** Edit here, then run `./install.sh` (the maintainer's own machine: `./install.sh --yes --answers examples/personal-overlay/answers.local.json`, his real answers, gitignored). Never edit `~/.config/herdr-app/mods/ledgr`, `mods/ledgr-pane` or `mods/my-tabs` in place. If an agent did edit the live copy (it happens during a build), run `./sync-from-live.sh` once to pull the changes back (it pulls the overlay mods into `examples/personal-overlay/`), review the diff, and go back to editing here.

Why a copy and not a symlink: Herdr refuses any import that resolves outside a mod's own folder, symlinks included, and the Claude Code hooks (in `~/.claude/settings.json` and each other chosen config folder's, `~/.claude-work/settings.json` in the examples) and the MCP server (in each folder's `.claude.json`) are registered against the installed path.

## Architecture in ten lines

1. Claude Code hooks (SessionStart, UserPromptSubmit, Stop) run `mods/ledgr/bin/adapters/claude/*.sh`. They inherit `HC_TERMINAL_ID` from the Herdr shell, so they can map terminal to session id, transcript path, cwd and turn; SessionStart and UserPromptSubmit also read the terminal's Herdr space (one `hc get $HC_TERMINAL_ID --json`, 300 ms limit, `ledgr_map.herdr_space()`) and record it. In a space listed in `spaces.disabled` they go quiet: the record and the map are written, but no spool event, no instruction, no landing and no extraction (`asks-instruction-space-off.txt` once to a session switched off, the mode's wording once when it is on again). They exit 0 fast, print nothing to the model's context except the ledgr-asks instruction (SessionStart, once after a missed blocker, once after an `asks.handoff` change), and ignore child or subagent processes (`LEDGR_INNER`, owner-pid rule).
2. Everything that changes state is a JSON event dropped into `~/.config/herdr-app/ledgr-data/spool/` with an atomic write: hooks, the capture box, panel actions, and the MCP server (`bin/mcp/ledgr_mcp.py`). `bin/lib/ledgr_spool.py` is the contract and has no Claude-specific imports.
3. One writer applies the spool to `ledgr-data/store.json` (source of truth) and `snapshot.json` (what the extractor reads), then deletes the spool file; it alone also moves what retention lets go into `archive/` (line 9) and idle sessions into `cold/` and back (line 10). The writer runs in an always-shown host copy because a panel block's mod copy only starts when first shown: the `ledgr` host block (props `{view: "host"}`, role `host`), or a mod with an engine copy (the maintainer's `my-tabs`, role `my-tabs`). Hosts elect one holder of `shared("ledgr.writer")`; the panel is a reader of `store.json` and falls back to being the writer only if no host answers within 4 s. The detail dialog is a second reader: its own copy of the mod (`detail.js`), opened per item, that reads `store.json` and the turn files itself, posts spool events and never pings, claims or runs a writer; both extend `reader.js` `Reader`. Never claim or ping from `herdr-app check` (it shares the window's shared state on 0.1.13): `config.js` `liveHome()` guards it.
4. Asks are declared first (by the MCP tool `declare_asks` when registered, else by a block), extracted as the fallback. The SessionStart hook puts the ledgr-asks instruction for the `asks.handoff` mode (`bin/lib/asks-instruction-ledgr.txt` or `-both.txt`; `prose` prints none; `instruct_block` stays the master switch) into the session's context, so the agent declares a blocker or a needed decision with `declare_asks` (written to `ledgr-data/mcp/<session>/<turn>.json` and spooled at once) or, without the tool, a fenced `ledgr-asks` block (bullets; a JSON array is still read). Only what the user personally must do, decide, provide or review is declared: a wait on the agent's own subagents, tools, builds or tests is never an ask, even as "I need", and the extractor's prompt holds the same rule (2026-11-10). At Stop the turn file `turns/<sid>/<turn>.md` gets the whole turn's assistant text (every text block since the prompt, the final message last; the `.json` beside it keeps the final message the extractor reads), and the extractor emits `pending`, resolves the turn's message uuid, and settles the tool declaration (quotes checked against that whole text) or reads that block (no model call); only a reply with neither goes to `claude-haiku-5-5` with forced JSON output (provider seam: `anthropic`, `openai-compatible`, `cli`). A blocking ask only the model found marks the session, and its next real prompt carries the instruction once (`instruct_reinject`). Either way it emits `asks`. Asks close three ways besides the person's Done: the agent's `resolve_asks` (when the user's message answers or drops one; `resolvedBy: "agent"`), a landed confluence (`"branch"`), or an answer that took (an ask answered by an `[A3]` ref or the answer sheet becomes `resolved`, `resolvedBy: "answer"`, at that turn's `asks` event unless the reply raised it again). A session in a space where ledgr is off declares nothing: it gets the off text instead of the instruction, and the MCP server writes nothing and answers `off: true`. An adapter's job is the instruction and the turns (`bin/adapters/README.md`); everything else is agent-neutral. Every ask carries a `level` (blocking, needed, optional); `extract.threshold` in `config.json` (shipped default needed; the maintainer's live config says blocking) decides which are open rows that count on the chip, and the rest are kept as folded suggestions.
5. Capture (`cmd-j`, `mod.open:ledgr`) opens over a working pane, parks a question with one keystroke, and accepts a clipboard quote only if it matches the saved turn text or `hc read`.
6. A message meant for an agent's prompt (the answer sheet, one answer, a confluence) is staged on the clipboard, its pane focused, and then pasted with Herdr's `terminal.paste` (what ⌘V runs) once Herdr reports that terminal focused on two looks in a row with the clipboard unchanged (`nav.js` `stageIntoPrompt`, `ui.pasteIntoPrompt`, default on). Never into a terminal with no agent or an agent waiting on its own prompt, and never Enter: the person adds a word of their own and sends it. When the focus is not confirmed within 600 ms, or the switch is off, it stays clipboard plus focus, as Go to anchor, Copy for prompt, `/btw` and Ask for a conclusion always are. One door: `stageIntoPrompt` is called only by nav.js `stageMessage` (one paste at a time per copy, the words of what happened), which only `reader.js` `Reader.stage` calls; neither `panel.js` nor `detail.js` defines `stage`, and copy methods never stage (11 rules in `test_no_keystrokes.py`). The dialog stages while open and closes once the paste is decided, since closing an overlay cancels its tasks. ledgr sends no keystrokes to any terminal: never `hc send` (it presses Enter and would submit a draft already in the prompt), never `hc keys` (Go to anchor pressed `ctrl+o /` until 2026-11-06; ctrl+o toggles Claude's transcript viewer), never `terminal.search`. `bin/tests/test_no_keystrokes.py` and `test_nav.mjs` enforce it (`terminal.paste` only inside `stageIntoPrompt`, without arguments, after the focus check). A staged confluence or answer sheet starts with a marker line (`ledgr confluence <branch> <item>`, `ledgr answers <session>`); the trunk's UserPromptSubmit hook sees it land and emits `confluence_landed` / `answers_landed` (`bin/lib/ledgr_landing.py`, `mods/ledgr/confluence.js`), one event per message when a prompt holds several (`detect_all`). Every staged message ends with one empty line (`nav.js` `promptText`), so a second paste into the same prompt does not run into the first.
7. Pins (`docs/design/Pins.md`, `docs/build-notes/BUILD-NOTES-pins.md`). In the capture box, ⌘S (`mod:ledgr` `"cmd-s": "ledgr.pin"`; `pinning.js` `PIN_KEY` and `pinDraft`) writes a `pin` spool event: the copied passage (up to 4,000 characters, line breaks kept), the box's line as its note, and an anchor (turn plus passage hash, uuid when known, never a position) from where the passage was found: a saved turn, else the screen (`hc read`), else unverified on a second ⌘S within 5 s. The writer keeps pins in their own `pins` map in `store.json`, beside `items`, so nothing that reads items (chips, counts, `snapshot.json`, refs, the archive, Forget) ever sees one; each pin carries its session's `source`, and the panel's `pin_note`, `pin_archive`, `pin_restore`, `pin_delete` apply by pin id even after Forget. A parked question carries pins through the box's `capture` Request (`request.pins`, at most 12, validated). Ask here stages `confluence.js` `pinsMessage` (marker `ledgr pins <session> <item>`, each passage quoted with `> ` and its provenance) through the paste of line 6; the trunk's hook emits `pins_asked` (quoted lines land nothing and give no refs: `ledgr_map.prompt_refs`), the question shows sent and is answered at that turn's Stop, and each pin records `answeredIn`. In a branch, `branch.js` `preamble` quotes the pins, the manifest gains a Given row, more than 24,000 pinned characters refuse the branch, Conclude prefills one entry per pin, and a landed confluence records `answeredIn` via the branch. No MCP tool reads pins yet.
8. The list and the detail dialog (`docs/design/Detail.md`, `docs/build-notes/BUILD-NOTES-detail.md`). The panel draws one line per item, pin or branch from `listing.js` `rowModel` (glyph, handle, one pill, the text's first line, a state word); Done (hovered or cursor row), Paste answer (an answer is ready) and Promote (below the threshold) are its only buttons. A click gives the list the keyboard (`focus_handle`, no `focusable` in `mod.json`); ↑ ↓, PageUp/PageDown, Home/End move a cursor over every line a click acts on, Enter does what its click does, Space checks a pin, Esc clears. A click or Enter on a row opens the dialog: `openOverlay(detailing.js detailSpec(…))`, `{view: "detail", session, kind, id, open, sel, opener, demo, archived}`, `kind: "dialog"`, 0.6 × 0.75, routed in `main.js` before `isCapture`. It shows the item whole (text, quote, the message with the passage marked, every section and action the expanded row had), its text selectable `TextView.markdown(…).selectable(true)` (the person's and pinned text escaped by `mdVerbatim`), and in the message and an ask's text and quote a clicked web link opens in the browser and a file path (`links.js` `linkify`, under `https://ledgr.invalid/path/…`) opens with `links.editor` from the record's folder or its git toplevel (`detail.js` `openLink`; `opener.js` holds the reading copies' only `exec`); one at a time (a second open closes the first; a sub-row retargets in place); Esc or a click outside closes it, drafts flushed and the Conclude text kept in its `localStorage`. It writes `shared("ledgr.detail")` `{open, closed}` on open and close; the panel draws the open row raised, and from the closed record restores the cursor, shows the dialog's last words, takes its typed answers, and takes the keyboard back (30 ms, again at 300 ms) or leaves it in the pane a message was pasted into. A pin opened from the lane or search opens in the shown session, so a question built from it parks there. Renderers in `views.js`; none of the five new modules is an engine file. The settings dialog (`settings.js`, `{view: "settings", opener, demo}`, routed beside detail) is a third reading copy that writes `config.json` only through `Reader.saveConfig` (`reader.js` `editConfig`: compare-and-swap, queued; the panel's threshold menu and space switch use it too) and shares `ledgr.detail` (kind "settings", no id) so one dialog is open at a time; every copy draws with `withScale(theme(), textScaleOf(cfg))` (`t.ts(n)`, `ui.textScale`; the host, the chip and the box read the writer's `shared("ledgr.ui").textScale`).
9. Retention (`docs/design/Retention.md`, `docs/build-notes/BUILD-NOTES-mod.md` 19). The writer's housekeeping (`writer.js` `houseDue`, `houseKick`, `housekeep`) runs at the first start after the upgrade, once a day, and within the hour once the saved store passes `HOUSE_SIZE` (768 KiB) and has grown `HOUSE_GROWTH` (64 KiB) since the last run ended (a retention change lets it run again): its own task, kicked from the start and the tick and never awaited (the writer keeps answering pings), one per generation, each await bounded and a named step the watchdog sees (kind `house`). A closed item past `retention_days` (3; whole days 1 to 30, read one way everywhere, `config.js` `retentionDays`; a dismissed one never before 7 days, as far back as the extractor's dismissed list looks) and every turn record past the newest `retention.turns` (12) per session, with the `textHead` of kept records past the newest `LIMITS.turnHeads` (2), go first into new files `archive/<session>/items-<ms>-<rand6>.jsonl` and `turns-<ms>-<rand6>.jsonl` (the folder `config.js` `safeName`, the mapping `bin/lib` `safe_name` and the MCP server use; each file at most 512 KiB, created once through `spool.js` `writeNew` and read back whole), and only then out of the store (`store.js` `removeItems`, `applySlim`, which take only what is still as planned, so drains run meanwhile). A run whose config is not `config.json` as read archives no item. Turn records are lean (no default `textPath`, no null field). The first run keeps the store as it was in `store.pre-retention-<ms>.json` and then sets `d.retention` `{v: 1, at}`. Pins, open items and handles never move to `archive/` (an idle session's open items go cold with it, line 10; pins and handles stay in the store). The panel's CLOSED fold ends with `archived (N) · show` (`session.archived`); shown, `Reader.loadArchive` reads the session's items files (each once, by name: written once) and the legacy `<yyyy-mm>.jsonl` (`listing.js` `archiveRecords`: an id the store holds wins; for one id, the newest file's last line) and lists them, state word "archived", no quick action; the panel's and the dialog's reads are bounded (`readArchiveWithin`, 10 s) and tried again. The dialog opens one read-only (props `archived`: its file) whose one action, Reopen, posts `{type: "restore", session_id, item, file, reopen: true}`; the writer reads the record before the batch applies and always consumes the event (a failure is its note), and `store.js` `restoreItem` puts the item back under its own id and handle (one another item holds now, or one the session's counter could hand out again, gives way to the next, the old kept as `handleWas`), always open, `session.archived` one fewer for an items file's line. A dialog open on an item a run archives shows it archived. Only the writer writes under `archive/` (`test_no_keystrokes.py` rule 14). The settings row "Closed items stay in the list" writes `retention_days` (1 to 30).
10. Cold sessions (`docs/design/Retention.md` 10, `docs/build-notes/BUILD-NOTES-mod.md` 20, `BUILD-NOTES-detail.md` 18). Freeze: the writer's cold run (`writer.js` `coldHouse`: `listHeld`, `freezeRun`, `coldSweep`), from the tick's `houseKick` only, once an hour (`COLD_EVERY_MS`, in memory), after Phase 1's run and never before its first has finished (`d.retention.v` 1), never in a start or a pass. It plans (`store.js` `planFreeze`, oldest idle first, `COLD_RUN_MAX` 40): a session idle more than `retention.coldDays` by its idle clock (`touchedAt`: the record's times, its items' `updatedAt`, its turn records' `stopAt`, `asks.at`, `retry.at`; never `seenAt`, and an act `seen` does not move it) that holds items or turn records, unless `freezeBlocker` (a deferred item, a confluence waiting to land, an active branch or resume on either side, a retry requested or running, an id whose safe name is empty, begins with "." or is shared) or the writer's `canFreeze` (an agent in a live pane mapped to it, the open dialog's session, the running pass's, `wantThaw`, `coldDays` 0) says no; open blocking asks do not keep it warm. Each session's file is written once (`spool.js` `writeNew`, read back; none begun after `COLD_RUN_MS`, 60 s), `config.json` is read again, and only then `commitFreeze` checks everything again (record, items, turn records and counts exactly as planned) and in one synchronous step carries the idle clock onto the record, takes the items and `d.turns[sid]` out and leaves the record as the stub, `cold: {file, at, n}` (`n` by level, so `countsOf` and `chips()` count any threshold without the file); files not committed are removed at once; one save. Thaw before apply: a pass reads every cold session its events need (`coldNeeded`: none for the pin ops, `forget`, `cold_reset`, an act `seen`; `branch_started` also its parent, `pins_asked` its `for_session`) and every one in `wantThaw` (`coldDays` 0, a due retry, a "mixed" session an older build added items to), at most `COLD_THAW_MAX` (50), with `readCold`, and brings it back with `thaw` (the store's copies win, `nextHandle` raised, a clashing handle renumbered with `handleWas`, the file added to `coldThawed`); `apply()` throws `ColdError` rather than apply to a cold session. Faulted and held: only a read that gets no answer is transient (the pass waits), and the third in a row for one session (`COLD_TIMEOUT_MAX`) faults it too; any other read error, an unparseable file or one not the session's faults that session alone (`cold.fault`; "cold/<file> is missing" only when a listing shows the file gone, else "is there but could not be read (<why>)"), and every other session's events in the pass apply; every event that needs a faulted session is copied create-only to `cold/held/<safe sid>/<its spool name>` (`holdEvent`) and leaves the spool, so the watchdog sees no stall; it replays in name order, once, when the session is back (the tick tries every `COLD_RETRY_MS`, 10 min; Try again posts `cold_retry`), reset (Use without its older items, `cold_reset`: `coldLost` kept, the session warm and empty) or forgotten. The sweep, after the freeze, first reads `store.json` again and saves and deletes nothing that run unless it is the text the writer last read or wrote (a store replaced by hand while Herdr runs); memory ahead of disk is then saved first, and the decision made only on the text written. It deletes a cold file only when it is provably redundant: by name, one its session's record lists as thawed (`coldThawed`, `COLD_GRACE_MS` 1 h after the thaw) or one of a session forgotten `COLD_KEEP_MS` (1 day) ago (`coldGarbage`); any other unnamed file of one recorded session that is not faulted, over a day old, at most `COLD_CHECK_MAX` (4) a run, is read and deleted only when the proof holds version by version, never by id or turn number (`coldUnproven`, `coldLacks`, `archiveCopies`): each item has an identical copy of the same session in `store.json` on disk, the session's named cold file or its archive, never merely a later one (a store put back from a backup and touched once is stamped later while holding less), and each turn record an identical copy in the store, the named file or the turns archive, or a store copy that differs only by a head the archive holds; otherwise it is kept for good, said once in `writer.log` (`keepCold`), listed by `--check` as recoverable (the manual way back is Retention.md 10.8). A file a record names (`cold.file`, `coldLost.file`) and everything in `cold/held/` are never swept. The reading copies read a shown cold session's file (`Reader.wantCold`: from a timer, bounded 10 s, 12 records cached) and merge it into a store they own (`store.js` `mergeCold`: copies beside the stub, out of `toText()` and `snapshot()`; never the fallback writer's live store, which the panel then shows as a clone), never write under `cold/` and never thaw: the first act on the session posts its event and the writer thaws it (`test_no_keystrokes.py` rule 15: only `writer.js` and `spool.js` write, unlink, make or remove anything under `cold/`). `snapshot.json` gains `cold: {sid: {file, fault}}`, and the extractor and the MCP server read a cold session's items from its file (`bin/lib/ledgr_extract.py` `session_items`, filtered as `snapshot()` filters), so `open_asks` answers as for a warm session; the server says `writer: "held"` only when it finds its event's copy in `cold/held/`. `store.json` stays `v: 1`: an older build sets aside a store of any other version as `store.corrupt-<ms>.json` and starts empty, so a version bump would wipe the ledger on a rollback (Rollback, below).

## Rollback past cold sessions

Before checking out and installing any build older than retention Phase 2 (2026-11-19), in this order (`Retention.md` 10.11):

1. `./install.sh --thaw-all` (with `--yes` when there is no terminal) and wait for "no cold sessions". It backs up `config.json`, writes `retention.coldDays: 0` and waits up to 120 s while the writer brings every cold session back; a writer must run (Herdr open, the host block or the panel shown), and it says "no cold sessions" only once the writer's claim shows it took the 0 and it has seen none cold twice.
2. A session it lists as unable to come back (the writer cannot read its file) first needs, in the panel, Try again (after putting its file back), Use without its older items, or Forget; then run `./install.sh --thaw-all` again.
3. Only then check out and install the older build. Files left in `ledgr-data/cold/` are inert for it.
4. After upgrading again, set the days in Settings ("Idle sessions move out of store.json"): `--thaw-all` leaves `retention.coldDays` at 0.

Skipping the first step loses nothing: `store.json` stays `v: 1`, the older build keeps the stubs, and on the re-upgrade the writer brings every "mixed" session back, the store's copy winning, handles unique, turn records merged. Meanwhile cold sessions show empty in the older build, an answer typed there to a cold ask (`[A1]` in the prompt, or the answer sheet) finds no item and is dropped without a word, and an ask the agent raises again there becomes a new item that sits as a duplicate beside the original after the merge.

## Vocabulary

its own copy of the mod, `detail.js`) · cursor (the list's keyboard position, an entry key; Enter does what a click on that line does) · housekeeping (the writer's retention run, 2026-11-19) · archive (`ledgr-data/archive/`: what housekeeping moved out of `store.json`, closed items and old turn records; archived items are read back under CLOSED and reopened from there) · restore (the event that brings an archived item back) · cold (a session nobody touched for `retention.coldDays`: its items and turn records in one file under `ledgr-data/cold/`, its record in `store.json`; 2026-11-19) · stub (a cold session's record, kept whole in `store.json` with `cold: {file, at, n}`: what the menu, the chips and the counts read) · freeze (the writer's move of a session into its cold file) · thaw (the writer's move back, before an event that needs the session applies; only the writer thaws, and showing a session never does) · merged (a reading copy's in-memory view of a cold session, its file's items beside the stub; never saved) · faulted (a cold session whose file the writer cannot read: `cold.fault`) · held (an event kept in `cold/held/` for a faulted session, replayed once it is back, reset or forgotten) · older (the panel's word for a cold session: OLDER SESSIONS, the "older" pill; "idle" is the agent's status, "archived" the archive's).

Two holes in the contract's sweep: its rule for a warm session would have deleted at once a day-old file whose session had just been thawed; and its guard, decide only when memory equals `store.json` on disk, would never have let it run, since `publish()` adds the chips' diagnostics to memory after every save, so the sweep saves first and decides on the text written. The outside review's blocker: the sweep deleted a file by name once no record named it and its session had moved on, which loses the only copy of a cold session's items when `store.json` goes back in time (a corrupt store set aside at a restart, a store put back from a backup) or after a reset with another file of the session on disk. Settled as "a cold file is deleted only when provably redundant": by name only a file its session's own record lists as thawed (`coldThawed`, an hour on) or a forgotten session's (a day on); any other unnamed file is read and deleted only when every item and turn record in it has an identical copy in `store.json` on disk, the session's named file or its archive (a later copy proves nothing: a store put back and touched once is stamped later while holding less; the cost, an orphan whose items changed afterwards stays for good); otherwise it is kept for good, said once in `writer.log`, listed by `./install.sh --check` as recoverable, with a manual way back (Retention.md 10.8), and the fault view (the panel's and the dialog's) names such a file before the person chooses Use without its older items. A second review round tightened that proof: it had matched ids and turn numbers, counted a turn record older than the oldest kept as cut, and taken archive lines of other sessions; now each item needs an identical copy, or a strictly later version, of the same session, each turn record an identical copy (or the store's copy minus a head the archive holds), and "older than the oldest kept" proves nothing, since a store that went back in time never cut a record. The sweep also reads `store.json` again first and does nothing when it is not the text the writer last read or wrote (a store replaced by hand while Herdr runs). A freeze in flight when the days go to 0 (Settings "never", `--thaw-all`): the freeze reads `config.json` again before its commit and `canFreeze` refuses every session at 0, and since the review found `--thaw-all` could still say "no cold sessions" while such a commit was saving, it says so only once the writer's claim shows it took the 0 and it has seen none cold twice.
