# Product landscape: branching, threading and forking in AI products (as of 5 Nov 2026)

Method and source-quality notes (read first):
- Primary = the vendor's own docs, help center, changelog or release notes. Secondary = blogs, reviews, forums, news. Every bullet below says which kind it is where that matters.
- Fetch limits: help.openai.com, openai.com, x.ai, support.discord.com, help.x.com and reddithelp returned HTTP 403 to my fetch tool. Where I cite OpenAI help-center or release-note content, I am relying on a web-search tool's summary of that page (the URL is the official page, but I could not read it directly). I flag those as "via search summary".
- npm registry publish timestamps (registry.npmjs.org) were used to date Claude Code and Codex CLI versions. Claude Code's CHANGELOG.md has no dates, only versions.
- "Unverified" means I found no official material confirming it.

## 1. General assistants (chat apps): what do ChatGPT, Gemini, Claude.ai, Grok, Perplexity, Copilot, Le Chat, Kagi, Poe, Raycast, DeepSeek and Qwen offer?

### Takeaway
"Branch in new chat" (a fork-to-new-conversation action on a message) is now the shared baseline in ChatGPT (Sept 2025), Gemini (rolled out from late April 2026), Raycast (July 2025) and Google AI Studio (user-reported). Claude.ai still appears to expose only the implicit edit/retry version arrows, with no official fork button. Nobody in this group ships a child thread that returns a result to the parent; the only "flow back" features are links, shared-project visibility and, in Microsoft Copilot, selection-scoped work on a passage.

### Cited Findings

ChatGPT (OpenAI)
- Feature: "Branch conversations on web", action label "Branch in new chat". Dated 4 Sept 2025 in the ChatGPT release notes. Trigger: hover a message, open the "More actions" menu, choose "Branch in new chat". Stated purpose: explore other directions without losing the original thread. Rolled out to all logged-in web users at launch. — [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) (via search summary; direct fetch blocked)
- Inheritance and parent: press coverage says the new chat carries the earlier context up to the branch point and the original chat stays as it was; the branch opens as a separate chat in the history list, not nested under the parent. These details come from secondary coverage, not the release note. — [TechRadar](https://www.techradar.com/ai-platforms-assistants/chatgpt/chatgpt-has-added-a-great-new-feature-and-its-one-i-know-ill-be-using-a-lot), [BGR](https://bgr.com/1959993/chatgpt-branch-conversations-new-feature-now-available/) (both via search summary only; I could not read the article bodies)
- Navigation back to the parent is just the chat list; nothing flows back (no merge, summary or link was reported). This is an absence in the sources, not a positive statement from OpenAI.
- Mobile flow ("..." menu, or press-and-hold on Android) comes only from an unofficial tips page: unverified. — [onecooltip](https://groups.google.com/g/onecooltip/c/Vpt26NLriCI)
- Shared projects: OpenAI's shared-projects announcement said the first version let members branch another member's conversation; the Help Center now says members of a shared project can create new chats and branch existing conversations, with the original kept intact and branches listed in the project. — [OpenAI shared projects post](https://openai.com/index/more-ways-to-work-with-your-team/), [Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) (via search summary)
- Canvas: highlight a section of text or code and "Ask ChatGPT" (edit that section or ask a question about it), or use the block comment icon on a paragraph. This is a selection-anchored side interaction, not a branch. The help page also says Canvas is not supported by GPT-5.5 or later models (stated in the search summary; verify before relying on it). — [What is canvas](https://help.openai.com/en/articles/9930697-what-is-the-canvas-feature-in-chatgpt-and-how-do-i-use-it) (via search summary)
- ChatGPT browser extension has a "Side chat": the 31 Aug 2026 release-note entry says side chat works in Edge, Brave and Vivaldi but not Opera; the Codex "What's new" page (27-31 Jul 2026) says the extension can bring selected page text into a side chat. — [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) (via search summary), [Codex What's new](https://learn.chatgpt.com/codex/whats-new)
- No consumer ChatGPT in-app "side chat" or later branching change was found after Sept 2025. The release-notes search snippets mentioned no later branching entries (via search summary; not exhaustively checked). — [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- Edit-message branching: an OpenAI community thread says editing an earlier input gives a new branch. That is a user post, not documentation; I did not find official OpenAI help text for the "< 2/2 >" navigator. — [OpenAI community thread](https://community.openai.com/t/feature-suggestion-undo-and-full-rollback-functionality-in-chatgpt/1044471)

Google Gemini app
- Feature: "Branch in a new chat". Trigger: below a response, open its menu and choose "Branch in a new chat" (web and mobile steps are the same). Deleting a branch does not delete the original, and deleting the original does not delete the branch. The help page does not say what is copied. — [Gemini Apps Help: Find and manage your recent chats](https://support.google.com/gemini/answer/13666746)
- Inheritance and naming: reports say the branch carries context only up to the chosen response, and the new chat is named "Branch ..." plus the original name; branching again from either chat is allowed. Secondary sources. — [Android Authority](https://www.androidauthority.com/google-gemini-branch-conversations-3649659) (via search summary), [Thoughts Brewing, 5 May 2026](https://thoughtsbrewing.com/blog/ai-quick-tips-322-branching-chats-in-gemini)
- Ship date: Android Authority first found it in a beta build; Josh Woodward (Gemini app head) announced a staged rollout around 22-24 Apr 2026, initially to about 20% of users (secondary reports disagree on 22/23/24 Apr; I did not retrieve his post). A single Japanese-language report puts mobile availability in late May to early June 2026 (single source, less certain). — [Android Authority](https://www.androidauthority.com/google-gemini-branch-conversations-3649659), [jetstream.blog](https://jetstream.blog/en/gemini-new-feature-branch-in-new-chat/) (both via search summary)
- Gemini release notes (page read up to character 100,000 of 160,000) show no branching entry; they list Canvas (2025.03.18) and a Gemini-in-Chrome side panel (2026.01.28), neither of which is conversation branching. — [Gemini release notes](https://gemini.google/release-notes/)
- Gems: no branching or threading feature found. Unverified.

- Qwen Chat: nothing found. Unverified.

### Inferences
- Among chat assistants, the dominant branch model is "copy history up to message N into a new top-level chat; no link back". ChatGPT and Gemini both do this, and both list the branch in the normal chat list. (Gemini names it "Branch: ...", which is the only visible lineage cue found.)
- Edit-and-regenerate sibling versions (arrows) are the default non-linear affordance everywhere else (Claude.ai, Kagi, DeepSeek, likely Grok and Le Chat), and none of the vendors in this group document how it works.
- Microsoft Copilot's "work only on this selected passage" is the only assistant-level feature that scopes a follow-up to part of an answer, but it does not create a durable child thread.

### Gaps
- Whether ChatGPT's edit-message branching has an official help page, and the exact in-app navigator, could not be confirmed (OpenAI pages blocked).
- Exact Gemini inheritance behavior and Woodward's announcement text were not retrieved from a primary source.
- AI Studio: no official doc or date for "Branch from here".
- Grok, Poe, Qwen, DeepSeek, Le Chat: no official evidence either way for edit/regenerate versions.

## 2. Open-source and third-party chat front ends, canvases and knowledge tools

### Takeaway
Third-party front ends invented most of the richer models: LibreChat's fork options (May 2024), Msty's Branch Explorer with side-by-side diff, Dust's branch-with-compaction-summary and "Branched from" link, and canvas tools (Flowith, Canvas Chat, Spine, tldraw starter kit, Obsidian plugins) where each message is a node and context is the path through the graph. The recurring UX problem is that users do not know what a branch inherits.

### Cited Findings

Chat front ends
- Open WebUI: official docs list "Fork a Chat" ("Branch a conversation into an independent copy from any assistant response"), which copies history up to that point into a new chat titled "<original title> (fork)"; requires the `chat.import` permission; unavailable while a response streams or in temporary chats. Also a `/fork` slash command and a "Side chat" (`/side` or `/btw`) that "opens a temporary chat tab that starts from the current conversation"; its messages disappear when the tab closes. Release dates not found. Selection-based "Ask"/"Explain" is not in the docs (the only matching feature is Comments on a selected passage); the "Ask/Explain" selected-text menu I found is a third-party browser extension. — [Open WebUI chat features](https://docs.openwebui.com/features/chat-conversations/chat-features/), [OpenWebUI Context Menu extension](https://chromewebstore.google.com/detail/openwebui-context-menu/gajjhdfmmlgfheccabafeinipgoonllm)
- LibreChat: "Fork" shipped in v0.7.2 (changelog dated 10 May 2024, "Fork Messages/Conversations"). Trigger: hover a message, click the fork icon. Three options: "Visible messages only" (direct path only), "Include related branches" (path plus the edit/regeneration branches along it), "Include all to/from here" (default; every message leading up to the target). Checkboxes "Start fork here" (fork runs from the target message to the latest) and "Leave out files". The new chat keeps the original title; "Remember" saves a default. Forking a shared chat via "Continue this chat" copies the selected branch into your account. v0.7.9 added rate limiting for forking. — [LibreChat fork docs](https://www.librechat.ai/docs/features/fork), [LibreChat v0.7.2 changelog](https://www.librechat.ai/changelog/v0.7.2), [LibreChat v0.7.9 changelog](https://www.librechat.ai/changelog/v0.7.9)
- Msty Studio: "Edit as Branch" on any message's actions menu saves an edit as an alternative path without overwriting the original. "Branch Explorer" lets you label and switch branches from a dropdown beside a branched message, use a mini map, and open a side-by-side diff of two branches. Separate "Split Chat" runs several models in parallel (a different feature). Dates not found. — [Msty responses docs](https://docs.msty.ai/studio/conversations/responses), [Msty Branch Explorer](https://docs.msty.ai/studio/conversations/branch-explorer)
- TypingMind: "Fork chat from here" in the three-dot menu of a message creates a new chat with all context up to that message; multiple forks from one message are allowed; docs say starting a thread inside a conversation is not available yet. A developer comment (secondary) describes "parallel chats" that only see their own branch and a "Finalize" feature that has a chosen model read all branches and merge them into one answer. Dates not found. — [TypingMind fork chats](https://docs.typingmind.com/chat-management/fork-chats), [Product Hunt thread via search summary](https://www.producthunt.com/posts/1164840)
- Dust (enterprise agent platform): "Branch a conversation". Trigger: 3-dots menu in the conversation's top right to branch from the latest agent message, or the per-message menu on any agent message. The branch inherits a compaction summary of the parent up to that point (as its first message), copies of the parent's files and tool outputs, the same space/project, tools and MCP servers; edits do not cross. Takes about 10-20 seconds. The parent is left unchanged but shows a note when a message was used as a branch point; the branch shows a "Branched from ..." link; branches can be branched again. Date not found. — [Dust: branch a conversation](https://docs.dust.tt/docs/user-documentation/agents/branch-a-conversation)
- LobeChat: its docs page for branching conversations was an empty placeholder when fetched, and a changelog entry titled "Exciting Launch of Branching Conversations Feature" exists; mechanics unverified. — [LobeChat docs](https://lobehub.com/docs/usage/features/branching-conversations), [LobeHub changelog](https://lobehub.com/fr/changelog/page/3)
- Juma: "Forking creates a new chat that includes everything up to that point, but none of the messages that came after" (via search summary). — [Juma help](https://juma.ai/help/forking-chats)
- Cassidy AI has a help article "Branching a chat" but I could not read it: unverified. — [Cassidy docs](https://docs.cassidyai.com/en/articles/13531993-branching-a-chat)
- SillyTavern: the official docs URL returned only a redirect stub. Per the third-party Timelines extension README, a "checkpoint" is a named chat branch stored as a new chat file with a link inserted in the original, created via the message-actions menu; the extension adds a graph view and can branch from any message or swipe; a community post says a refactor to implement chat branching natively was in progress in early 2026. Swipes (alternate regenerations) as a concept: unverified from official docs. — [SillyTavern Timelines README](https://gitee.com/mayfan11/SillyTavern-Timelines), [r/SillyTavernAI snapshot, Feb 2026](https://reddit.sentinel-team.org/posts/1qud1b6/snapshots/2026-02-04T09%3A41%3A28.191197Z)
- Loom (Janus/moire): blog post dated 9 Feb 2021 describes an interface for GPT-3 "multiverses". Read mode shows the current node and its ancestors as one history with a tree/chapter sidebar; Visualize mode shows a tree diagram where you edit nodes, expand/collapse, add children or siblings and merge a parent node; generate N continuations and take weighted stochastic walks. The post says counterfactual branches "can be merged into main" without detail. Code: socketteer/loom (README: tree view, block multiverse view, hotkeys for parent/child/sibling, bookmarks, checkpoints, search over ancestry). An Obsidian reimplementation exists (cosmicoptima/loom). — [Loom: interface to the multiverse](https://generative.ink/posts/loom-interface-to-the-multiverse/), [socketteer/loom](https://github.com/socketteer/loom), [cosmicoptima/loom listing](https://awesome.ecosyste.ms/projects/github.com%2Fcosmicoptima%2Floom)
- LM Studio, Jan, Chatbox: no branching documentation found. Unverified. (Searches returned only other products.)

Canvas and node-based chat
- Flowith: "Context Playground" (blog, 8 Jan 2026). Each AI output is a node; right-click to duplicate a node and explore a parallel branch; Batch Mode generates several variations; multi-select nodes and "Group Nodes" to combine their context as input to the next prompt (the merge-like action); hover a link to cut it so low-quality context stops flowing; trim a single context block. Vendor blog (primary but promotional). — [Flowith Context Playground](https://flowith.io/blog/context-playground)
- Canvas Chat (open source, MIT): reply to any message creates a branch; select text inside a node and click "Branch" to create a highlight-excerpt node; multi-select nodes to combine context; a context visualization shows which messages are included. No date on the page. — [Canvas Chat docs](https://ericmjl.github.io/canvas-chat)
- Spine: Chat Block has a branch button under each message that starts a new thread from that point with the history and context up to it; the previous thread is preserved. — [Spine chat block docs](https://docs.getspine.ai/chat-block)
- tldraw "Branching chat" starter kit (developer template): branches are created by dragging connections between node ports; sending a message traces backward through connected nodes to rebuild the history. tldraw computer is an experimental natural-language workflow canvas (Gemini 2.0 Flash, per the-decoder) where outputs feed next blocks and processes can branch and loop. — [tldraw branching chat kit](https://tldraw.dev/starter-kits/branching-chat), [the-decoder](https://the-decoder.com/tldraw-unveils-experimental-natural-language-computer-powered-by-gemini-2-0/)
- Obsidian community plugins: Canvas Branch Chat (fork a conversation from any canvas node, label directions, inherit context up the ancestor chain), Cymose (each message is a JSON Canvas node, a branch is a second child), Canvas LLM, AI Chat as Markdown (branches as nested headings). — [Canvas Branch Chat](https://community.obsidian.md/plugins/canvas-branch-chat), [Cymose](https://community.obsidian.md/plugins/cymose), [AI Chat as MD](https://community.obsidian.md/plugins/ai-chat-as-md), [Obsidian Stats tag](https://www.obsidianstats.com/tags/branching-chat)
- CanvasConvo (arXiv 2605.15848, v2 listed 15 Sep 2026; LMU Munich, Aalto, Bayreuth): research prototype; branch from any chat message or canvas node, the branch duplicates history up to that point; each branch appears as a nested sidebar entry, a badge at the branch point in chat, and a zone on the canvas. A 5-day field study with 24 participants logged 165 conversations, 1,225 messages and 79 branches; one participant said "I didn't know what the branch knows and what it doesn't know". — [arXiv](https://arxiv.org/html/2605.15848)
- Heptabase: chat lives on whiteboards; right-click a card for New Chat, select text in a card and "Add to Chat", @-mention cards, and save a response as a card. No branching feature found. — [Heptabase: Work with AI](https://wiki.heptabase.com/work-with-ai)
- Tana: AI chats are linear, each answer uses the whole chat as context, and a response can be inserted into the chat's parent node. No branching found. — [Tana AI chat](https://tana.inc/docs/ai-chat)
- Notion AI: no branching found. 7 Apr 2026 release added read-only share links for AI chats. — [Notion releases 2026-04-07](https://www.notion.com/es/releases/2026-04-07) (via search summary)
- Whimsical AI, Napkin, Kosmik, Scrintal: no conversation-branching evidence found. Unverified.
- Bare-bones sibling versions (edit/regenerate) are an SDK pattern with a "2 of 3" switcher in LangChain, assistant-ui and Ably AI Transport docs. — [Ably: branching, edit and regenerate](https://ably.com/docs/ai-transport/features/branching), [LangChain branching chat](https://docs.langchain.com/oss/python/langchain/frontend/branching-chat)

### Inferences
- LibreChat's three fork scopes are the clearest published statement of the design question "do sibling edit/regenerate branches come with the fork?". Dust is the only one found that summarizes the parent into the child instead of copying the transcript.
- Canvas tools give a real "merge" (Flowith Group Nodes, Canvas Chat multi-select, TypingMind Finalize), but merging means combining context for a new prompt, not reconciling two transcripts.
- Visibility of inherited context is an unsolved UX problem (CanvasConvo participant quote; Cursor hides parent context on purpose, see section 3).

### Gaps
- Dates for Open WebUI, Msty, TypingMind, Dust, Spine, Canvas Chat features not found.
- SillyTavern's current native branching state and swipe semantics not confirmed from official docs.
- LM Studio, Jan, Chatbox, LobeChat mechanics, Cassidy, Whimsical, Napkin, Kosmik, Scrintal: not verified.

## 3. Coding agents: which let you spawn a child conversation from the middle of a parent and bring the result back?

### Takeaway
Claude Code (/subtask forked subagent) and Cursor (side chats, pulled back with an @-mention) are the clearest "spawn from the middle, return a result" designs; Roo Code, Devin and Warp's orchestration return a summary or artifacts from children that start with narrower context. Pure "fork" commands (Codex /fork, Warp /fork, Factory /fork, VS Code /fork, Cursor Fork Chat, Claude Code /branch and /fork) produce independent copies with nothing flowing back automatically.

### Cited Findings

Claude Code (Anthropic) -- the richest set
- `/branch [name]` (renamed from `/fork` in v2.1.77, npm 16 Mar 2026): copies the conversation to this point, switches you into the copy, and keeps the original, which you return to with `/resume`; CLI form `claude --continue --fork-session`. The branch inherits history; "Allow for this session" permission grants carry over within the same process but not with `--fork-session`; in-flight background subagents keep running and report into the new branch; a connected Remote Control client follows you into the branch. The /resume picker lists branches as separate rows, grouping entries of the same session under an expandable row. — [Manage sessions](https://code.claude.com/docs/en/sessions), [CHANGELOG 2.1.77](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), [npm registry](https://registry.npmjs.org/@anthropic-ai/claude-code)
- `/fork [prompt]` (since v2.1.212, npm 16 Jul 2026): copies the whole conversation into a new background session (own row in agent view) and you keep working; the copy normally makes its own git worktree; "Nothing the copy does enters the original on its own", except via cross-session messaging. Clicking the confirmation's name switches you into the copy. ### Inferences
- Three distinct patterns: (a) fork = independent copy, no return path (Claude Code /branch and /fork, Codex /fork, Warp, Factory, VS Code, Cursor Fork Chat); (b) side thread = child that sees the parent but is kept out of the parent's history, with an optional pull-back (Claude Code /btw, Codex /side, Cursor side chats, Open WebUI side chat); (c) delegate = child with narrower or fresh context that returns a summary/artifact (Claude Code subagents and /subtask, Roo, Devin, Warp orchestration, Copilot /delegate).
- Only /subtask (result auto-posted into the parent) and Cursor's @-mention (user-triggered pull of the side chat's context) combine "inherit the parent mid-conversation" with "bring something back". Amp rejected forking in favor of handoff plus thread mentions (pull by reference, not by inheriting).
- Ephemeral vs durable is a real split: Codex `/side`, Claude Code `/btw` and Claude Desktop's side chat are not persisted, while Cursor side chats persist and stay attached to the parent.

## 4. Collaboration tools as prior art: which model is closest to what a branching AI chat needs?

### Takeaway
No single model fits. Slack and Discord threads (spawn from a message, with an opt-in way to surface a reply in the parent) map to side chats; Zulip topics map to naming/organizing parallel conversations; Google Docs comments map to selection-anchored questions with resolve; email References and quote posts map to lineage links; comment trees (HN) map to reply trees where every node has one parent. Of these, the Slack/Discord "thread on a message, shown in the parent as a stub" and Google Docs "anchor + resolve" models are closest to what Cursor, Claude Code and Codex built.

### Cited Findings
- Slack: hover a message and click "Reply in thread"; a checkbox lets you also post the reply to the channel ("Send reply to this channel"); notifications are per thread (in channels you are notified only if you started, replied or were mentioned); a Threads view lists the threads you are in with unread at the top. The page does not say how deep threads nest. — [Slack: use threads to organize discussions](https://slack.com/help/articles/115000769927-Use-threads-to-organize-discussions)
- Zulip: "Topics in Zulip fill the role of threads in other chat apps"; every conversation is labeled with a topic, there is no threads sidebar, and "there's nothing special about the first message in a thread"; conversations can run for hours or days and replies stay in context. Zulip's own page, so the superiority claims are the vendor's. — [Zulip: introduction to topics](https://zulip.com/help/introduction-to-topics)
- Discord: a thread is created from a message (hover, ellipsis, Create Thread; title optional, created when the first message is sent); public threads must be created from an existing message; threads auto-archive after inactivity (API durations 60, 1440, 4320, 10080 minutes) and posting again unarchives unless locked; creating one needs "Create Public/Private Threads" permission. — [Discord Threads FAQ](https://support.discord.com/hc/en-us/articles/4403205878423-Threads-FAQ), [Discord developer docs: Threads](https://docs.discord.com/developers/topics/threads) (both via search summary; direct fetch blocked)
- Google Docs comments: anchored to a text selection; replies stay grouped under the comment; "resolve" closes the discussion, resolved comments stay viewable and can be re-opened; an @-mention can assign an action item. — [Google Docs: comments](https://support.google.com/docs/answer/65129)
- Email: RFC 5322 section 3.6.4 says the "References:" field may be used to identify a "thread" of conversation; In-Reply-To names the parent message(s); a reply's References builds on the parent's References plus the parent's Message-ID; some implementations assume a single parent, and the spec discourages multi-parent References. — [RFC 5322 section 3.6.4](https://www.rfc-editor.org/rfc/rfc5322#section-3.6.4)
- Hacker News (as a comment-tree data model): each item has a `parent` and ordered `kids`, and stories carry a `descendants` count; the collapse control is a UI layer on that tree. — [HackerNews/API](https://github.com/HackerNews/API)
- Reddit comment trees, Twitter/X quote posts: unverified (the Reddit and X help pages returned HTTP 403 and I found no other official source).

### Inferences
- Closest to a branching AI chat: Slack/Discord "thread from a message" (child scoped to a parent message, parent shows a stub, an optional "also send to channel" bubble-up) plus Google Docs' anchored comment with resolve (a question about one passage that ends). Cursor's "Ask in Side Chat" on a selection and @-mention pull-back, and Codex's ask-in-side-chat from selected transcript text, follow this pattern.
- Email References and Dust's "Branched from" link are the lineage model: a branch is a new top-level item that records its parent. This fits the "fork" pattern and costs little UI.
- Zulip topics suit organizing many parallel branches by name (cf. Claude Code `/branch <name>`, Msty branch labels), but a topic has no notion of a child inheriting the parent's content.
- Comment trees (one parent per node) match edit/regenerate version trees, not forks that need multi-parent merges (email's own spec discourages multi-parent References, a hint at how awkward merges are).

### Gaps
- Reddit and X quote-post behavior unsourced.
- Slack thread nesting depth not stated on the page I read.

## 5. Which products are doing something genuinely different from "edit and regenerate"?

### Takeaway
Baseline: edit-and-regenerate (sibling versions with a switcher) is everywhere, and "copy history into a new top-level chat" (ChatGPT, Gemini, Raycast, LibreChat, Open WebUI, TypingMind, Juma, Spine) is table stakes. The genuinely different ideas are: child threads that stay attached to a parent and hide parent context from the transcript (Cursor side chats); forked subagents that inherit the whole conversation and post a result back (Claude Code `/subtask`); ephemeral side conversations (Codex `/side`, Claude Code `/btw`, Open WebUI side chat); summary-seeded or goal-seeded branches (Dust, Amp handoff, Zed New From Summary, Warp `/fork-and-compact`); and graph/canvas models where context is the path or selection of nodes (Flowith, Canvas Chat, tldraw kit, Obsidian plugins, CanvasConvo).

### Cited Findings (pointers into sections above; no new claims)
- Table-stakes fork-to-new-chat: [ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes), [Gemini help](https://support.google.com/gemini/answer/13666746), [Raycast v1.101.0](https://www.raycast.com/changelog/1-101-0), [LibreChat fork](https://www.librechat.ai/docs/features/fork).
- Attached, hidden-context child thread with pull-back: [Cursor help: side chats](https://cursor.com/help/ai-features/side-chats).
- Forked subagent with automatic return: [Claude Code subagents: fork](https://code.claude.com/docs/en/sub-agents.md).
- Ephemeral side conversation: [Codex slash commands](https://learn.chatgpt.com/codex/reference/slash-commands), [Claude Code /btw](https://code.claude.com/docs/en/interactive-mode.md), [Open WebUI chat features](https://docs.openwebui.com/features/chat-conversations/chat-features/).
- Summary- or goal-seeded child: [Dust](https://docs.dust.tt/docs/user-documentation/agents/branch-a-conversation), [Amp handoff](https://ampcode.com/news/handoff), [Zed agent panel](https://zed.dev/docs/ai/agent-panel), [Warp forking](https://docs.warp.dev/agents/local-agents/interacting-with-agents/conversation-forking.md).
- Canvas/graph context: [Flowith](https://flowith.io/blog/context-playground), [Canvas Chat](https://ericmjl.github.io/canvas-chat), [tldraw kit](https://tldraw.dev/starter-kits/branching-chat), [CanvasConvo](https://arxiv.org/html/2605.15848).
- Branch comparison UI (diff of two branches): [Msty Branch Explorer](https://docs.msty.ai/studio/conversations/branch-explorer).

### Inferences
Quick matrix (derived from the findings above):

| Product | Mechanism | Parent visible/continues? | Inherits | Flows back |
|---|---|---|---|---|
| ChatGPT / Gemini / Raycast | Fork to new chat | Yes, separate chat | History to the branch point | No |
| LibreChat | Fork with 3 scopes | Yes | Path, path plus sibling branches, or all | No |
| Dust | Branch with compaction | Yes, shows note | Summary, files, tools | Link "Branched from" only |
| Claude Code /branch | Switch into a copy | Original resumable | Full history, some grants | No (merge-back requested) |
| Claude Code /fork | Background copy | Yes, keeps running | Full history | No (cross-session messaging only) |
| Claude Code /subtask | Forked subagent | Yes, parent continues | Full history | Result posted into parent |
| Claude Code /btw, Codex /side | Ephemeral side question | Yes | Whole conversation | No (by design) |
| Cursor side chat | Durable attached child | Yes | Hidden parent history | @-mention pulls context in |
| Amp handoff | New thread from a goal | Old thread stays | Edited draft prompt and files | Thread mentions pull in |
| Roo / Devin / Warp orchestration | Delegated child | Parent paused or coordinating | Instructions only | Summary / artifacts |
| Flowith / Canvas Chat | Graph nodes | All visible on canvas | Selected nodes | Group nodes into next prompt |

- Likely reading for design: the "what does the branch inherit" question has at least five answers in production (full copy, copy up to a message, summary of the parent, hidden reference context, nothing/instructions only), and CanvasConvo's participant quote suggests users need that made visible.
- "Merge" is mostly absent: flows back are links, summaries, @-mention pulls or artifacts, not reconciliations of two transcripts.

### Gaps
- No usage or quality data comparing patterns beyond CanvasConvo's 24-person study (a single research prototype).
- Whether Anthropic, OpenAI or Google plan a merge-back or nested view for chat apps: nothing official found.
